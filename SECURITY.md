# Security policy

OpenMaze 0.1 is experimental research software. No release is approved for
production or critical infrastructure. The default branch is the only development
line receiving fixes; there is no supported production release.

Report vulnerabilities privately through this repository's **Security → Report a
vulnerability** option, if enabled. If that option is unavailable, do not publish
credentials, exploitable details, user data or a working exploit in a public issue.
Ask the maintainer to establish a private reporting channel first. A monitored
private channel must be confirmed before a public stable release.

Include affected commit, reproduction on synthetic local fixtures, expected and
observed boundary, impact, and any safe mitigation. Do not target third-party
systems to demonstrate impact. Acknowledgment within seven days is a proposed
maintainer target, not an established response SLA.

Coordinate disclosure after a fix and regression test where possible. Do not
claim permanent AI containment, audited cryptography, RFC 9421 compliance,
production isolation, or availability guarantees from this prototype.
